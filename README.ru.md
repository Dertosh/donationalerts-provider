# DonationAlerts Provider — плагин OBS

[English](./README.md) | [Русский](./README.ru.md)

Нативный плагин OBS Studio на C++ для Windows x64. Плагин должен запускать локальный API внутри OBS; отдельный Node.js-сервер не требуется.

> Независимый проект сообщества; не является официальным продуктом DonationAlerts или OBS Project и не одобрен ими. Названия и товарные знаки принадлежат соответствующим владельцам.

> **Важно:** OAuth-подключение, realtime-донаты через Centrifugo WebSocket и передача событий локальным WebSocket-виджетам реализованы. История загружается REST-опросом раз в 5 секунд. Цели и опросы пока не реализованы.

## Установка готового плагина

Для текущей сборки требуется **OBS Studio 32.2.2 x64**. Сборка для другой версии OBS и 32-битная версия не поддерживаются.

1. Полностью закройте OBS, в том числе из области уведомлений рядом с часами.
2. Получите файл `donationalerts-obs-provider.dll` из сборки проекта или релиза.
3. На Windows плагин устанавливается для всех пользователей в `%ProgramData%`. Установщик сам запросит права администратора через окно UAC.
4. Перейдите в корневую папку проекта и запустите установщик:

   ```powershell
   .\tools\install-obs-plugin.ps1
   ```

   Скрипт проверит версию OBS и наличие DLL, Qt Schannel TLS-бэкенда и файлов локализации, затем установит их в `%ProgramData%\obs-studio\plugins`. Для DLL из другого места укажите `-DllPath "D:\Downloads\donationalerts-obs-provider.dll"`. Для нестандартного каталога OBS передайте `-ObsInstallRoot "D:\Apps\obs-studio"`. Чтобы установить Debug-сборку, используйте `-Configuration Debug`.
5. Запустите OBS. Если плагин загрузился, в меню **Инструменты** появится пункт **DonationAlerts Provider**. Панель использует язык OBS: доступны английский и русский.
6. Откройте окно настроек через **Инструменты → DonationAlerts Provider**. Это обычное отдельное окно, не док OBS.
7. В панели введите ID и секрет приложения DonationAlerts. Зарегистрируйте показанный в панели redirect URI в настройках приложения и нажмите **Подключить аккаунт**. Подтвердите доступ в открывшемся браузере; секреты OAuth хранятся зашифрованными средствами Windows для текущей учётной записи.
8. Выпустите ключ с доступом к донатам. По умолчанию ключ бессрочный; при необходимости снимите флажок **Без срока действия** и задайте срок. Секрет показывается один раз после выпуска и может быть скопирован кнопкой. Токен виджета не заменяет OAuth-подключение аккаунта.

Чтобы удалить плагин, сначала закройте OBS, затем удалите папку `%ProgramData%\obs-studio\plugins\donationalerts-obs-provider`.

## Подготовка окружения разработки

Необязательно, если у вас уже есть готовая DLL. Для самостоятельной сборки нужны:

- OBS Studio **32.2.2 x64**;
- Visual Studio 2022 с компонентом «Разработка классических приложений на C++»;
- Windows SDK **10.0.26100**;
- CMake **3.28 или новее**;
- `curl.exe`.

Из корневой папки проекта запустите в PowerShell:

```powershell
.\tools\prepare-obs-sdk.ps1
```

Скрипт скачивает официальный архив исходников OBS, проверяет его SHA-256, настраивает CMake и собирает `libobs` и OBS Frontend API. Необязательный параметр `-Configuration Debug` собирает SDK в конфигурации Debug вместо Release. Исходники SDK и сборочные файлы сохраняются в игнорируемой папке `.obs-sdk`.

Затем соберите и проверьте плагин:

```powershell
cmake -S .\obs-plugin -B .\obs-plugin\build -G "Visual Studio 17 2022" -A "x64,version=10.0.26100.0"
cmake --build .\obs-plugin\build --config Release
ctest --test-dir .\obs-plugin\build -C Release --output-on-failure
```

Готовый файл появится здесь:

```text
obs-plugin\build\Release\donationalerts-obs-provider.dll
```

Вместо скрипта можно установить файлы командой CMake из PowerShell с правами администратора, находясь в корневой папке проекта. OBS должен быть закрыт:

```powershell
cmake --install .\obs-plugin\build --config Release --prefix "$env:ProgramData\obs-studio"
```

Перед установкой закройте OBS. CMake положит модуль в каталог плагинов OBS под `%ProgramData%`.

## Текущие возможности и ограничения

Плагин добавляет отдельное окно настроек **DonationAlerts Provider**, подключается к DonationAlerts по OAuth 2.0 Authorization Code и запускает локальный HTTP API на `127.0.0.1:4041` и WebSocket событий на `127.0.0.1:4043`. OAuth-токены хранятся зашифрованными через Windows DPAPI. При запуске OBS плагин автоматически восстанавливает подключение из сохранённых данных: обновляет access token при необходимости, загружает профиль и запускает Centrifugo WebSocket. Первоначальную OAuth-авторизацию нужно выполнить один раз вручную в окне **Инструменты → DonationAlerts Provider**.

Чтобы увидеть, какие данные приходят от DonationAlerts, включите внизу окна настроек **Режим отладки**. В области отладки показываются REST-ответ истории и входящие сообщения Centrifugo; значения известных OAuth/realtime-токенов маскируются. Откладочная область хранится только в памяти и ограничена последними 300 строками. Ответы могут содержать имена донатеров и сообщения; не отправляйте скриншоты или скопированный вывод публично без проверки.

- `GET /health` — проверить запуск локального API;
- `GET /api/widget-tokens` — список сохранённых ключей и их метаданных; истёкшие ключи помечаются `active: false` и остаются доступны для отзыва;
- `POST /api/widget-tokens` — выпустить ключ; `expiresAt=0` означает бессрочный ключ, положительный Unix timestamp в миллисекундах задаёт дату истечения. Старое поле `expiresInMinutes` оставлено для совместимости (до 24 часов);
- `POST /api/widget-tokens/revoke` — отозвать ключ по его ID, в том числе после истечения срока;
- `GET /api/widget/data` — получить профиль и последние донаты; требуется заголовок `Authorization: Bearer <widget-token>`.
- `GET /api/v1/alerts/donations` — API-совместимый прокси DonationAlerts, включая query-параметры; использует локальный ключ виджета для авторизации, а OAuth-токен остаётся в OBS.
- `GET /api/v1/user/oauth` — профиль в формате ответа DonationAlerts, без Centrifugo socket-токена.

Для этих API-совместимых путей замените только базовый URL DonationAlerts на `http://127.0.0.1:4041`; пути, query-параметры и JSON-формат остаются прежними. Например, `https://www.donationalerts.com/api/v1/alerts/donations?per_page=30` становится `http://127.0.0.1:4041/api/v1/alerts/donations?per_page=30`. Передавайте временный ключ плагина как `Authorization: Bearer <widget-token>`. Плагин выполняет запросы к DonationAlerts от имени подключённого аккаунта и возвращает его HTTP-код и JSON-ответ. Сейчас проксируются только чтение профиля и истории донатов; остальные пути DonationAlerts намеренно не открыты. История напрямую проксируется только при подключённом аккаунте OBS.

Для этих scoped read-only маршрутов разрешены браузерные источники с HTTP(S) Origin (в том числе удалённо размещённые OBS Browser Sources); каждый запрос всё равно обязан иметь действительный ключ с `read:donation-events`. Остальные локальные административные и provider-маршруты сохраняют ограничение Origin.

Метаданные ключей хранятся зашифрованными через Windows DPAPI до явного отзыва. Новые ключи бессрочные по умолчанию; при выборе срока укажите календарную дату истечения, после чего ключ действует до конца этого дня по местному времени. Срок больше не ограничен 24 часами. Уже выданные ключи сохраняют прежний срок, поэтому ранее истёкший ключ нужно заменить новым. Истечение срока отключает доступ к API и WebSocket, но не удаляет запись из списка; отозвать можно и активный, и истёкший ключ. Одновременно сохраняется не более 500 записей — чтобы выпустить новый ключ при заполненном списке, сначала отзовите ненужные.

```js
const response = await fetch("http://127.0.0.1:4041/api/v1/alerts/donations?per_page=30", {
  headers: { Authorization: `Bearer ${widgetToken}` }
});
const donations = (await response.json()).data;
```

Пример запроса из OBS Browser Source:

```js
const response = await fetch("http://127.0.0.1:4041/api/widget/data", {
  headers: { Authorization: `Bearer ${widgetToken}` }
});
const { profile, donations } = await response.json();
```

`ws://127.0.0.1:4043/api/widget/events` — WebSocket-поток событий. Передайте временный ключ вторым subprotocol: `donationalerts-widget-v1`, `<widget-token>`.

Для HTTP-запросов к API, включая кросс-origin браузерные виджеты OBS, передавайте ключ в заголовке `Authorization`, а не в URL. WebSocket API браузера не поддерживает произвольные заголовки авторизации, поэтому локальный WS принимает временный ключ во втором subprotocol. OAuth-токен DonationAlerts никогда не передаётся виджету.

### Демонстрационная веб-страница

Откройте файл `obs-plugin\demo\widget-demo.html` в обычном браузере или используйте установленную копию `%ProgramData%\obs-studio\plugins\donationalerts-obs-provider\data\demo\widget-demo.html` как Browser Source. Страница принимает ключ из параметра `token` URL страницы, сохраняет его в локальном хранилище браузера и автоматически подключается. При повторном открытии страницы ключ восстанавливается из хранилища; если параметр не передан и сохранённого ключа нет, его можно ввести вручную. Новое событие показывается только при получении push-сообщения по сокету; данные истории не используются для имитации событий. Страница загружает историю при подключении, по ручному запросу и после нового realtime-доната; периодического опроса REST со стороны страницы нет. Например, добавьте к адресу страницы `?token=ВАШ_ВРЕМЕННЫЙ_КЛЮЧ`.

Дополнительные минимальные примеры для Browser Source (оба используют один и тот же тип ограниченного widget token, выпущенного в панели OBS):

- `obs-plugin\demo\widget-plugin-api.html` — запрос снимка через API плагина `GET /api/widget/data` и realtime-события через локальный WebSocket;
- `obs-plugin\demo\widget-donationalerts-api.html` — запросы по API-совместимым маршрутам `GET /api/v1/user/oauth` и `GET /api/v1/alerts/donations?per_page=30`.
- `obs-plugin\demo\widget-stream-alert.html` — анимированное всплывающее уведомление о новом донате с именем, суммой и сообщением;
- `obs-plugin\demo\widget-stream-feed.html` — компактная лента последних донатов.

Два последних примера используют общий `widget-stream.css` и `widget-stream.js`, но показывают разные способы чтения истории:

- **Алерт** загружает историю через API плагина `GET /api/widget/data`; realtime-события идут по WebSocket плагина.
- **Лента** получает историю через API-совместимый маршрут DonationAlerts `GET /api/v1/alerts/donations?per_page=30`, авторизуясь временным ключом провайдера. Новые realtime-события также поступают по WebSocket плагина.

Ключ для обоих вариантов выпускается в панели OBS и должен иметь доступ **События донатов**; это ограниченный ключ провайдера, а не OAuth-ключ DonationAlerts. Откройте страницу в браузере для предварительного просмотра, введите ключ и нажмите **Подключить**. После успешной проверки форма сворачивается; нажмите **Настройки ключа**, чтобы снова открыть поле и заменить ключ. Кнопка **Тест алерта** или **Пример записи** по умолчанию скрыта и показывается только в отдельном режиме предпросмотра `?preview=1`. Для Browser Source используйте локальный файл из `%ProgramData%\obs-studio\plugins\donationalerts-obs-provider\data\demo\` либо тот же файл из репозитория; для чистого оверлея можно добавить `?token=ВАШ_ВРЕМЕННЫЙ_КЛЮЧ&overlay=1`. Режим `overlay=1` скрывает настройки и тестовые кнопки, фон остаётся прозрачным.

В этих примерах токен из панели передаётся только в `Authorization: Bearer <widget-token>`. Это не OAuth-токен DonationAlerts: плагин использует OAuth внутри OBS, а Browser Source получает только ограниченный ключ виджета.

1. Запустите OBS с установленным плагином и подключённым аккаунтом DonationAlerts.
2. В панели плагина выпустите временный ключ с включённым доступом **События донатов**.
3. В URL Browser Source добавьте `?token=ВАШ_ВРЕМЕННЫЙ_КЛЮЧ`; для ручного ввода откройте страницу без параметра.

Параметр `token` удаляется из адресной строки после загрузки страницы. Для HTTP ключ отправляется только в заголовке `Authorization`; для локального WS ключ передаётся subprotocol и не попадает в URL запроса сокета. Ключ демо хранится в `localStorage` профиля браузера, доступен скриптам этой страницы и может быть извлечён пользователем с доступом к профилю. Кнопка **Отключиться** удаляет его из хранилища. URL источника OBS с `?token=` также сохраняется в настройках OBS. Используйте отдельный временный ключ и отзывайте его при утечке. Страница должна работать на том же компьютере, что и OBS. Realtime-донаты идут по сокету DonationAlerts → плагин → локальный WS виджета; REST используется только для истории.

Административные запросы панели требуют внутренний заголовок `X-Admin-Token`, который хранится в памяти плагина и не выводится в журнал. Секрет временного ключа показывается только при выпуске; разрешены только read-only scope событий донатов, целей и опросов. Для проверки ключа плагин хранит только SHA-256-хеш и метаданные; они зашифрованы Windows DPAPI и сохраняются в `%APPDATA%\obs-studio\plugin_config\donationalerts-obs-provider-tokens.dat`. Действующие ключи виджетов остаются рабочими после перезапуска OBS до истечения срока или отзыва. Доступ к файлу привязан к учётной записи Windows, под которой запущен OBS.

**Ограничения:** Realtime-подписка использует OAuth/Centrifugo endpoints из [официальной документации DonationAlerts](https://www.donationalerts.com/apidoc) и требует разрешение `oauth-donation-subscribe`. Если realtime-сокет не подключён, панель OBS показывает ошибку и демо не имитирует события из REST-истории. Цели и опросы пока не передаются. Ключи виджетов и OAuth-токены сохраняются зашифрованными; снимок данных находится в памяти и сбрасывается при закрытии OBS. Redirect URI должен быть зарегистрирован в настройках приложения DonationAlerts точно в указанном виде.

Не пробрасывайте локальный порт во внешнюю сеть. При ошибке загрузки проверьте, что OBS закрыт во время копирования, установлена правильная версия **OBS 32.2.2 x64**, DLL находится в `bin\64bit`, а журнал OBS не сообщает об отсутствующих зависимостях или занятом порте `4041`.
