# Участие в проекте

[English](./CONTRIBUTING.md) | [Русский](./CONTRIBUTING.ru.md)

Спасибо за помощь в развитии DonationAlerts Provider. Мы принимаем сообщения об ошибках и предложения через GitHub Issues, а изменения — через Pull Request.

## Перед созданием Issue

- Сначала проверьте, не создано ли уже такое обращение.
- В сообщении об ошибке укажите версии OBS и Windows, шаги для воспроизведения, ожидаемое и фактическое поведение, а также очищенный от секретов журнал OBS.
- Не публикуйте OAuth-секреты приложения, access/refresh-токены, ключи виджетов, коды авторизации, имена донатеров или личные сообщения. Удалите их со скриншотов и из журналов.
- Используйте Issue для обсуждения или описания ошибки, Pull Request — для предложенных изменений кода или документации.

## Pull Request

1. Создайте fork репозитория и отдельную ветку для изменения.
2. Ограничьте изменения одной задачей и обновите связанную документацию.
3. Соберите проект и запустите регрессионные тесты по командам из README. Укажите результаты и релевантные версии OBS/Windows в описании Pull Request.
4. Не добавляйте credentials, результаты сборки, скачанный OBS SDK или несвязанные форматирующие изменения.
5. Если изменение связано с Issue, добавьте ссылку и опишите изменение поведения или шаги ручной проверки.

Пожалуйста, подписывайте каждый коммит в соответствии с Developer Certificate of Origin (DCO), версия 1.1. Подпись подтверждает, что у вас есть право предоставить этот вклад на условиях лицензии проекта; она не передаёт авторские права и не требует отдельного CLA. Добавить подпись можно командой:

```text
git commit -s
```

В сообщение коммита добавится строка `Signed-off-by: Name <email>`. Текст DCO доступен на <https://developercertificate.org/>.

Отправляя вклад, вы соглашаетесь предоставить его на условиях **GPL-2.0-or-later**, как и остальной проект. Авторские права на свой вклад вы сохраняете.

## Локальная проверка

Регрессионные тесты provider-сервера можно запустить без сборки OBS SDK. Выполните из корня репозитория в PowerShell:

```powershell
cmake -S .\obs-plugin\tests -B .\build\provider-server-tests -G "Visual Studio 17 2022" -A x64
cmake --build .\build\provider-server-tests --config Release
ctest --test-dir .\build\provider-server-tests -C Release --output-on-failure
git diff --check
```

Эти же регрессионные тесты Windows x64 автоматически запускаются для push в `main` и Pull Request. Полная сборка OBS-плагина по-прежнему требует подготовки OBS SDK, описанной в README.

Если меняли виджет, дополнительно проверьте его в Browser Source OBS и убедитесь, что тестовые элементы скрыты в режиме трансляции/оверлея.
